## 4. Bugs

### P1-1 Blank ribbon when a floating window has focus and scroll is not clamped

Repro (r03; scenario `qa/scenarios/r03_floating_focus_display_shrink_scroll.json`):
```
display 1920x1050; add 1..6 (tiled); focus_index 6; add 10 floating=true; window_focused 10; display 1280x800
```
Observed: after the display event every column has `on_screen=false`, `map.viewport` = `1.0`-`1.0`, `focus=null`. `gather` (which the app sends right after every display change, `Controller.swift:screenChanged`) does not repair it. The ribbon recovers only on `focus_left`/`focus_right` or when the dialog closes.

r02: same setup, then `window_removed 5`, `window_removed 6` while dialog focused: viewport goes 0.80-1.0 then 1.0-1.0, all remaining columns parked.

Expected: scroll clamped to `[0, content - avail]` on any display or remove event; some column visible.

Likely cause: `core/src/engine.rs` `reveal()` only runs when a tiled cursor exists (`if let (Some((c, _)), Some(_)) = (self.cursor(), self.display)`), so with floating focus nothing clamps `st.scroll` and `layout::reveal`'s clamp is never reached. SPEC says `gather` is used after wake/display change, but it does not re-clamp scroll.

Real-world trigger: a Save or Preferences dialog open while the monitor is unplugged or the lid is closed.

### P1-2 App minimum width treated as a user drag (silent width drift)

Repro (r06; `qa/scenarios/r06_min_size_echo_widens_column.json`):
```
display 1920x1050; add 1,2,3,4; focus_index 2; window_resized id=2 frame.w=1000
```
Observed: column 2 `width_frac` goes 0.5 to 0.5304 (adopted `Px(1000)`). Nothing was dragged. Our last written frame was 942, the app clamped to its minimum (1000), and `Controller.swift:113` only suppresses echoes within 3 px of the last write (`FrameApplier.isEcho`). `Engine::adopt_width` then stores the width and clears the toggle_full restore memory.

Expected: a width the app reports because it refused our size should not change the layout. Or, if the app's minimum should be honored, that should be an explicit rule. Needs on-device confirmation: this live AX case could not be exercised (no Accessibility on the mini).

### P2-1 Focus direction ignored when a floating window has focus

Repro (r01): `add 1, add 2, add 3, add 10 floating, window_focused 10, focus_right`.
Observed: focus goes to window 2 (leftmost visible column). `focus_left` does the same. Expected: focus the column in the pressed direction, or the column nearest where the dialog was.

### P2-2 Tiling a floating window appends at the far end and jumps the viewport

Repro (r05): `add 1..5, focus_index 2, add 9 floating, window_focused 9, toggle_float`.
Observed: window 9 becomes the last column, viewport moves from 0.20 to 0.67, four columns away from the user's position. Expected: tile next to the focused column (or follow `new_window` config), without a large scroll jump.

### P2-3 Unknown focus_window id flashes the ribbon HUD

Repro (r04): `add 1, add 2, command focus_window arg=77`.
Observed: no error, `show_map=true` (HUD flashes), no change. Expected: `show_map=false` (or an error).

### Notes (not bugs)

- `focus_index` beyond range silently clamps to the last column (documented in core/README). Users pressing 9 with 3 windows get window 3. Worth a UX decision.
- Engine error plans are never shown to the user; `Controller.apply` only NSLogs them.

## 5. Tooling / QA gaps

1. `core/tests/props.rs:53` hard-codes `ProptestConfig::with_cases(300)`, so `PROPTEST_CASES` (and any overnight "50000 cases" request) silently runs 300 cases. Fix: use `ProptestConfig::default()` (which reads the env var) or read the variable explicitly.
2. `qa/check_plans.py` flags every map with floating focus as "map must have exactly one focused column" (false positive by design). It also cannot see blank-ribbon or focused-off-screen states; `qa/scenarios/analyze.py` covers those.
3. `qa/scenarios/gen_scenarios.py` and `analyze.py` are reproducible; re-run them after any core change.

## 6. Prioritized list

- P0 (crash / data loss): none found in 25 scenarios, 484+ plans, or fuzz.
- P1-1: Blank ribbon with floating focus after display change or column close (r02, r03). Fix in engine: clamp scroll whenever content or avail changes, even without tiled cursor; make `gather` re-clamp.
- P1-2: App minimum-width clamp adopted as a user drag (r06, s16). Needs an on-device check, then a rule in Engine/Controller.
- P2-1: Focus direction ignored from floating windows (r01).
- P2-2: Tile-from-float lands at the end with a large scroll jump (r05).
- P2-3: focus_window with unknown id shows HUD (r04).
- P2 tooling: props.rs ignores `PROPTEST_CASES`; check_plans.py false positives on floating focus.
