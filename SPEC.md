# Ribbon — a calm scrolling window manager for macOS

Windows live side by side on one horizontal ribbon per display (nine virtual desktops per display, each its own ribbon). You never "arrange";
you just open things and glide left/right. Built for people with ADHD: zero setup,
one obvious way to do each thing, constant orientation cues, every action undoable.

## Principles
1. **Zero config.** Works the second Accessibility is granted. Settings exist but nobody needs them.
2. **Always know where you are.** A Liquid Glass "ribbon map" pill appears on every change, then fades.
3. **One modifier, few keys.** `⌃⌥` + arrows. That's 90% of usage.
4. **Nothing is lost.** Undo (`⌃⌥Z`) for any layout change (moving focus or switching desktops is not a layout change). Quitting puts every window back, even after a crash (original frames are mirrored to
   `~/Library/Application Support/Ribbon/originals.json`, deleted on clean quit/pause-restore).
5. **Calm motion.** Springy, short, never flashy. Respects Reduce Motion / Reduce Transparency.
6. **Not overengineered.** One process, one permission (Accessibility). Private APIs are kept to two: `_AXUIElementGetWindow` (window ids; essential) and MultitouchSupport (three-finger scroll; optional, `dlopen`'d at runtime — if it or a symbol is missing the feature is off and Ribbon works unchanged).

## Architecture (one app, one process)

```
Ribbon.app (SwiftUI + AppKit, LSUIElement menu-bar app)
 ├─ Platform/   AX windows, AX observers, Carbon hotkeys, screens      (Swift)
 ├─ UI/         menu bar, onboarding, command bar, ribbon-map HUD      (SwiftUI, Liquid Glass)
 └─ links libribbon_core.a  ──  C ABI: one JSON-in/JSON-out function    (Rust)
core/  (Rust crate `ribbon_core`, staticlib + rlib)
     pure state machine: events in → layout plan out. No macOS calls. Fully unit-tested.
```

Why this split: the layout/state logic is the part that must be *correct*; Rust + pure
functions + property tests make it deterministic and testable headless (overnight on the
Mac mini). Everything that touches macOS is Swift, where AX/AppKit/SwiftUI are first-class.
The FFI boundary is a single function with JSON so it's trivial to debug, log and replay.

- Global hotkeys: Carbon `RegisterEventHotKey` (no Input Monitoring permission needed).
- Only permission: Accessibility.
- Min macOS 26 (Liquid Glass). Swift 6.2-compatible source, Swift 5 language mode.

## Core FFI contract (`core/include/ribbon_core.h`)

```c
typedef struct RibbonEngine RibbonEngine;
RibbonEngine *ribbon_engine_new(const char *config_json);   // NULL/"" → defaults
void          ribbon_engine_free(RibbonEngine *);
char         *ribbon_engine_handle(RibbonEngine *, const char *event_json); // returns Plan JSON
void          ribbon_string_free(char *);
```

All coordinates: **global top-left origin points** (AX space). Ids: `u32` CGWindowID.

### Config (all optional)
```json
{ "gap": 12, "outer_gap": 12,   // invalid keys fall back to their default individually; outer_gap is clamped to keep 100px usable "default_width": 0.5,
  "width_presets": [0.25, 0.333, 0.5, 0.667, 0.75, 1.0], "new_window": "right_of_focused",
  "scroll": "keep_visible",    // or "center", or "center_on_overflow" (like keep_visible, but a column not fully in view is centered, clamped to the content)

```

### Events (`{"type": ..., ...}`)
| type | fields | meaning |
|---|---|---|
| `display` | `id:u32, frame:{x,y,w,h}` (visible frame, AX coords) | add/update a display (one engine instance per display; the core itself knows only one) |
| `window_added` | `id, pid:i32, app:string, title:string, frame, floating:bool`, optional `width_hint:frac`, optional `take_focus:bool` (default true) | new manageable window; floating ⇒ tracked but not tiled. New column width = `width_hint`, else `app_widths[app]`, else `default_width` (snapped to the nearest preset). `take_focus` false (an app in the background opened it): it joins in the same place but takes no focus (`plan.focus` null), changes no shown tab and does not scroll |
| `window_removed` | `id` | closed/destroyed (also drops a shelf entry) |
| `window_replaced` | `old, new, pid:i32, app:string, title:string` | a native macOS tab group showed another of its windows: `new` takes over everything `old` had, in place: column slot and width, stack row and height share, Ribbon tab-group membership and active tab, floating mode and remembered tile width, desktop, focus, focus history and floating anchor, learned size floors, and its entries in every desktop's undo/redo stacks. `jump: true` (nothing glides), `changed` = `[new]` (the new window is always written to the old one's frame), no focus request (the OS already focused the new tab), no HUD. Title and app come from `new`. An unknown `old` is ignored (no-op plan); `old == new` only refreshes the metadata. A `new` the core already has (its `window_added` arrived first) gives up its own slot for `old`'s, and the focus its add took goes back to the previous window (focus history) |
| `window_minimized` | `id` | yellow button: the window leaves the ribbon (neighbours close the gap, focus moves on) and is **shelved**: `id → {pid, desk, width, floating, app, title}`. A later `window_added` with the same id (Dock un-minimize, command bar) restores it: its remembered width, placed right of the focused column on **its own desktop** (switching there with a jump + "Desktop n" toast if that is not the active one), focused. With `take_focus` false (the app un-minimized it while the user is in another app) it goes to the same place, but focus, the shown tab, the desktop and the viewport stay put and the map does not show. Shelf entries are dropped by `window_removed` (destroyed, app terminated). Unknown ids are ignored |
| `app_hidden` | `pid` | ⌘H: every managed window of the app (all desktops) is shelved exactly like `window_minimized`, flagged `hidden`, remembering left-to-right order. The host stops scanning that app while hidden |
| `app_shown` | `pid`, optional `front:id`, optional `take_focus:bool` (default true) | the app was unhidden: its hidden shelf entries return in their original relative order, each on its own desktop with its width, right of that desktop's focused column; `front` (else the last restored) is focused and its desktop activated. `take_focus` false (unhidden while the user is in another app): the same places and order, but no focus, desktop switch, scroll or map. Windows minimized before the hide stay shelved |
| `window_focused` | `id` | OS focus changed (click, ⌘-Tab; the host also sends it when an app is activated from the Dock/Spotlight/⌘-Tab, for that app's focused window if managed, since activation fires no AX focus event) → ribbon scrolls to it; a window on another desktop switches to that desktop (toast "Desktop n", no focus request: the OS is already there) |
| `window_title` | `id, title` | |
| `window_refused` | `id, frame` | the app refused our size (fixed-width window) and settled on `frame`: a hard constraint, adopted exactly as the column width (and the window's height in a stack): no minimum clamp, no preset snap, no undo step, no write-back, neighbours keep the normal gap. A later `cycle_width` etc. may try a preset again; one refusal event per attempt. A window that settled *wider* than asked (it would not go narrower) only holds its column there while it must: the column keeps its own width (a fraction, or dragged px), takes it back as soon as its own width is at least the held px in the band it plans in, whatever brought that about (another display, undo/redo or `toggle_full` bringing back a layout that held it), and a session saves its own width, not the held px (after a relaunch the app is asked again). A window that settled narrower keeps that width until a command sets another. The host also reconciles 450ms after things go quiet: any visible window whose actual size differs from its planned frame (cell-increment terminals, a swallowed last drag event) is reported the same way, once per distinct size, so the gap between adjacent visible windows is always the configured gap measured from actual frames |
| `window_resized` | `id, frame` | user dragged size → column adopts that width (as px); in a stack of ≥2 also that window's height (as a share). One drag = one undo step ("resize"). If the adopted size differs from the reported frame (clamp, snap), the window is in `changed` so it ends on the plan's frame; the app waits until resize events stop for 250ms before writing it |
| `scroll_by` | `dx:f64` (px) | trackpad scroll: move the viewport offset by `dx` (positive = towards later columns). Continuous, clamped to the ribbon extent (first to last rest offset, see `scroll_end`) with a rubber band (pushing past an end is resisted to 40% and capped at 60px; coming back is 1:1). Focus and undo untouched; `show_map` true; `changed` = windows whose frame changed. Ignored with no display/windows or a non-finite `dx` |
| `scroll_to` | `id`, `x:f64` | the host lines the core up with tiles that are still gliding (a new swipe catches the previous one's release): scroll so the tiled window `id` sits at logical `x`, as a frame's `lx` reports it. Absolute and unresisted, clamped to the rubber band's reach (60px past either end), so catching a release inside the band does not jump the tiles the way `scroll_by` of the difference would (it resists past an end). Part of the gesture it joins; focus, undo and `show_map` untouched. Ignored for a window that is not tiled on this desktop, with no display or a non-finite `x` |
| `scroll_end` | optional `velocity:f64` (px/s, same sign as `dx`) | fingers lifted: the viewport always settles on a **rest** and pulls back any rubber band. Rests: every column start up to the ribbon's end plus the offset that puts the content's end flush with the display's (never blank room after the last column; a start within 32 px of that end is the same stop, only the first start, 0, always stays); with `center`, every column centred (the first and last too). It picks the rest nearest the viewport projected 0.12s ahead by `velocity` (capped at 6000 px/s); a release still moving at 400 px/s or more after at least 32 px past the rest behind it (a flick) moves on to the next rest in its direction at least, further when the projection reaches it, and a flick back cancels. Focus goes to the column nearest the middle of those wholly in view (distance to its span, then to its centre; the whole ribbon when none is), same row if already focused in it, else the top window. Columns equally near the middle (every pair of half-width columns is), within 1 px: a swipe that moved the ribbon on from where its gesture began focuses the side it moved towards (later column forward, earlier backward); one that came back to where it began keeps the focused column, so a nudge never flips focus (a release without a gesture start: the first column at the ribbon's start, the last at its end). The viewport stays on the rest it settled on (the column is whole in view there). Not undoable |
| `command` | `name`, optional `arg` | see commands |
| `query` | — | return plan without changes |
| `snapshot` | — | plan with `session: {active, desktops:[{index, columns:[{windows, width:{kind:"frac"|"px"|"fixed", value}, heights?}], floating, focus, scroll}]}` (non-empty desktops only); nothing else changes |
| `restore_session` | `active`, `desktops` (as above) | rebuild every desktop from a saved layout over the windows the core already knows (the host re-adds them first and maps saved identities to current ids). Unknown ids are ignored; windows the session does not name stay on their desktop, appended after the restored columns; live floating windows stay floating; stack heights survive only if the whole stack came back; bad widths fall back to the default; focus per desktop (unknown → live focus → first); an invalid `active` keeps the current desktop. Clears undo/redo, `jump: true`, asks for focus |

Plan field `shelf: [{id, app, title, desk (1-based), hidden}]` lists minimized/hidden windows, most recently shelved first. Shelved windows are in no layout, `map`, or `frames`. The command bar lists them after live windows with a dimmed icon and a "Minimized" / "Hidden" tag; choosing one sets `AXMinimized` false (minimized) or unhides the app, and the resulting `window_added` / `app_shown` restores it as above.

### Commands
`focus_left`, `focus_right`, `focus_up`, `focus_down` (within a stacked column),
`move_left`, `move_right`, `cycle_width` (next preset), `cycle_width_back`, `cycle_height` (focused window in a stack: height ⅓ → ½ → ⅔ of the column, others share the rest; single window: no-op with a hint),
`toggle_full` (focused column full width; again restores), `stack` (merge focused window
into the column on its left), `unstack` (pop focused window into its own column on the right),
`center` (scroll so focused is centered), `focus_index` (arg: n, 1-based column, clamped to the last; navigation, not undoable. Hotkeys ⌃⌥⇧⌘1…9 and the command bar's "window 3" call it through the app, which answers "Only 3 windows" for a number past the last column instead of clamping),
`focus_window` (arg: id; ids beyond `u32` are ignored; a window on another desktop switches to it first),
`switch_desktop` (arg: n 1-9; invalid n is an `error`), `switch_desktop_back` (previous desktop; twice toggles), `move_to_desktop` (arg: n 1-9; see Desktops), `focus_previous` (jump to the previously focused window; focus history skips closed windows, so twice toggles between two windows; not undoable), `undo`, `redo`, `toggle_float` (focused window float ↔ tile; a window re-tiled after floating gets back the column width it had, else the new-window width),
`move_to_index` (arg: n, 1-based target column, or `{"id", "index"}`; moves that window (default: focused) into its own column at n, clamped, and focuses it; undoable),
`focus_first` / `focus_last` (first / last column, top window; toast "First window" / "Last window" only if focus moved, else "That's the end of the ribbon"; navigation, not undoable), `equalize_heights` (focused stack back to equal shares; undoable "heights"; toasts "Heights evened out" / "Already even" / "Stack windows first"),
`move_first` / `move_last` (the focused column, all its windows, to the start / end of the ribbon, keeping focus; toasts "Moved to the start" / "Moved to the end", "Already first" / "Already last" at the ends; undo label "move"), `stack_right` (mirror of `stack`: the window joins the column on its right as that column's first window, and the column it leaves goes if it was alone; "No more windows on the right" at the last column; undo "stack"),
`grow_width` / `shrink_width` (the focused column ±5 % of the usable width from wherever it is, preset or not, stored as a fraction clamped like `set_width`; toast "Width 55 %", or "As wide as it gets" / "As narrow as it gets" with no undo step and the full-width restore kept; undo "width"), `grow_height` / `shrink_height` (the focused window's share of its stack ±5 %, the others split the rest equally, clamped like a drag; toasts "Height 55 %", "As tall as it gets" / "As short as it gets", "Stack windows first", "Tabs fill the column"; undo "height"), `move_up` / `move_down` (swap the focused window with its neighbour in the stack, its height going along; in a tabbed column that moves the tab; toasts "Moved up", "Moved to tab 2 of 3 · App", "Top of the stack" / "Bottom of the stack", "Already the first tab" / "Already the last tab", "No stack here"; undo "move").
`gather` (no-op for layout; plan re-emits all frames — used after wake/display change).

### Tabs, drag, presets
- `toggle_tabs` (2+ windows in the focused column; on a lone window it is `tab_with` toward its left neighbour, the right one if it is the first column, toast "Tab group: A + B", "Nothing to tab with" if alone; undo label "tabs"), `tab_with` (arg `"left"|"right"|-1|1|{direction}`: the focused window joins that neighbour column as its newest tab, shown, and the column becomes tabbed; one undo step; error "No column there" without a neighbour), `move_window_to` also takes position `tabs` (like `into`, but the target becomes a tab group; the drop of a window on another window's title bar, top 40pt of a non-tabbed column), `next_tab` / `prev_tab` (wrap; navigation), `focus_up/down` cycle tabs in a tabbed column. `column.mode` = stacked | tabbed (`map.columns[].tabbed/active`, session `tabbed/active`). A tabbed column reserves a 30pt strip (no gap) at its top, flush on the window for the tab bar (`plan.tab_bars`: `{column,x,y,w,h,on_screen,active,focused,tabs:[{id,app,title}]}`); the active window fills the rest, the other tabs get the same size but are parked at the display's right edge (`on_screen` false) - no dependence on raise order. Tab switches set `jump`. A new window opened with focus in a tabbed column joins it right after the active tab and becomes active. Height commands and height drags are ignored in a tabbed column.
- `move_window_to` arg `{id?, column (1-based, before the move), position: before|after|into, row? (into: index among the column's other windows)}`: undoable ("move"), keeps the width, focuses the window, ignores unknown ids, errors on a bad column/position, no-op for a lone window on its own column.
- `set_width_presets` arg `[fractions]`: live config change (no undo, no layout change). Default presets 25/33/50/66/75/100; the 25 % step (345px on 1440pt) is below the 360px drag floor, so it is reachable by cycling but not by dragging on displays narrower than ~1500pt.
- `set_width` arg fraction in (0, 1] (or `{fraction}`): the focused column's width, undoable ("width"), clears the full-width restore, toast "Width 66 %" even when unchanged. Below the drag floor (max(360px, 20 %)) it is lifted to the floor, except that every configured preset stays reachable (cycling already lands on 25 %). Hotkeys `width_step n` (Swift) map ⌃⌥⌘1…6 to the nth preset of the active list.
- Focus mode (Swift, `Platform/FocusLogic.swift`, `UI/DimOverlay.swift`): Settings `otherWindows` = normal | dim | blur (old `dimOthers` true reads as dim). The one overlay panel per display below the focused window also holds an `NSVisualEffectView` (`.hudWindow`, `.behindWindow`) masked with the same even-odd cutouts (focused window + the focused column's tab bar) under a 12 % black tint. ⌃⌥B / command bar "Focus mode" / menu bar item toggles a session choice (follow Settings | on = blur | off), never saved. While it is on, scrolling is `center` (the focused column stays in the middle of the band); leaving restores the Settings scroll mode and keeps the view where it is. Reduce Transparency: a 62 % dim instead of blur; Reduce Motion: no cutout glide or fade. Shown on all displays (a sharp second screen is the loudest thing left in view); hidden while a window is dragged by its title bar (the focus ring hides too, and returns at the landed frame) and, in direct mode, while the fingers move (it returns as the windows settle). Click-through: clicking a blurred window focuses it and the blur moves. Fades are kept on a clock (`UI/PanelFade.swift`): a refresh while the panel fades in never cuts the fade to full opacity, and a fade-out that is placed again turns back from where it has got to. Under the snapshot swipe overlay, which covers the real panel, the overlay draws the dim itself (`SwipeOverlay.setDim`): every ribbon tile but the focused one carries a black tint of the dim's opacity (Blur: its frosted twin under the light tint, lifted by the material's haze (white in the light appearance, near black in the dark one), and the frosted backdrop likewise, clipped to the usable area), the backdrop's tint has the focused window and its tab bar cut out and follows them frame by frame, and at release the cutout glides to the new focus on the tiles' spring while the tints trade places. The real panel is placed for the new focus under the overlay at full opacity, so the overlay fades onto a dim that is already there.
- Swift: dim overlay (Settings `otherWindows`, `dimLevel`), tab bar panels, title-bar drag (`Platform/WindowDrag.swift`, rule in `Platform/Chain2Logic.swift`).

### Layout rules
- Ribbon = ordered columns; column = 1+ windows stacked vertically, one width. Heights are equal by default; each window may hold a height share (sum 1).
- Width = fraction of display visible width (minus outer gaps) or absolute px after a user drag.
  Dragged widths are clamped to `[max(360px, 0.2 * avail), avail]` (then snapped to a preset within 24px).
- Height: shares of the column's usable height (`avail_h - gaps`). `cycle_height` gives the focused window ⅓/½/⅔ (next preset above its
  current share, wrapping; others split the remainder equally). A dragged height is adopted as a share, clamped so every window keeps
  `max(120px, 0.15 * avail_h)`, and snapped to ⅓/½/⅔ within 24px. Stacking, unstacking, moving or removing a window resets that column to equal heights.
- Pixel edges are rounded per edge (`right = round(left + w)`), so neighbouring columns never overlap and the gap is exact.
  A dragged width received before any display is known is stored as-is and clamped at layout time.
- Columns laid out left→right with `gap`; viewport = display width. Scroll offset is state.
- `keep_visible`: after focus change, scroll minimally so the focused column is fully visible
  (if wider than the screen, align its left edge). `center`: center focused column.
- Off-viewport windows: placed just beyond the display edge (x = display.right - 1 for the
  right side, x = display.left - w + 1 for the left side) so macOS keeps them alive but out
  of sight; `on_screen=false`.
- New window: inserted as a new column right of the focused one, gets focus. Not when an app in the background opened it (`window_added.take_focus` false; the host says so unless the window's app is frontmost or the system has that window focused): it joins at the same place, but focus, the shown tab and the viewport stay put (a column inserted left of the viewport pushes the scroll along, so what is in view does not move), and the map does not show. Once the app comes to the front its focused window is reported like any other focus change and the ribbon goes to it. Focus-change notifications of an app that is not frontmost are ignored for the same reason, unless the system has that window focused. The same holds for windows coming back: an app that un-minimizes a window or is unhidden while the user is in another app (by itself, or by another app) brings them back quietly (`take_focus` false on `window_added` / `app_shown`); a Dock click or ⌘Tab activates the app, which takes the ribbon there. How recently the app launched does not count: a launched app's first window often comes a moment before the app is active, but one launched in the background (`open -g`, a login item) opens its windows just as soon, and focusing it would bring that app to the front. That first window joins quietly and the app's activation reports it (asked again 0.1 s and 0.4 s later while the app is still in front and has not answered).
- **Desktops** (OmniWM's model, independent of macOS Spaces; each display has its own nine, see Displays; desktop 1 on start). Every known window is on exactly one desktop; each desktop is its own ribbon
  (columns, widths, heights, scroll, focus, focus history, undo stack). New windows go to the active desktop. Windows of inactive desktops get a
  frame in every plan, parked at `x = display.right - 1` with `on_screen=false` (1pt sliver, like off-viewport windows), so macOS keeps them alive; floating
  ones are listed in `floating_parked` instead. `switch_desktop n` makes n active, focuses its remembered window and re-settles its scroll; an empty desktop
  parks everything (focus null); the host then activates Finder so keystrokes do not reach a parked window. `switch_desktop_back` flips to the previous desktop. `move_to_desktop n`: the focused window leaves for n, into its own column
  right of that desktop's focused column (first column if empty; its width is kept; floating stays floating); you stay on the current desktop and focus moves
  to the neighbour the window left behind; the target keeps its own focus. Closing a window on an inactive desktop cleans up there. `focus_previous` is per desktop.
- Floating focus: while a floating window has focus, the anchor is the last tiled window; `focus_left/right/up/down` all
  re-enter the ribbon at the anchor (never a no-op). `toggle_float` back to tiled inserts right of the anchor; floating a
  tiled window anchors on its left neighbour, so it returns to the same place.
- Removing the focused window focuses its neighbor (left, else right), never "nothing" when
  windows remain.
- Undo and desktops: undo is **per desktop** (each keeps its own 50 steps, undo and redo). Switching desktops is navigation like focus: never recorded, never undone.
  `move_to_desktop` is one undo step on the *source* desktop; its snapshot also holds the target, so "Undid: move to desktop" brings the window back to its old
  column and redo sends it again. Undo on a desktop never touches another, except that.
- Undo stack: snapshots of (columns, widths, heights, scroll, focus) before each layout-changing command (not focus/center commands) and before an adopted mouse resize (consecutive resize events of the same window share one snapshot); max 50.
  Each snapshot also stores a label of the command that produced it. After undo/redo the focused column is revealed
  (minimal scroll), so it is on-screen even if the display changed since the snapshot. Windows opened since the snapshot are re-inserted right after their left neighbour (not appended), and the floating-focus
  anchor / focus history are reconciled with the restored state. Closing a window is not a layout
  change, so undo after a close reverts the last layout change and the window stays closed; the toast says what was
  undone ("Undid: full width").
- Toasts (`Plan.toast`, otherwise null): undo/redo "Undid: <full width|move|width|height|resize|stack|unstack|float>" / "Redid: …",
  "Nothing to undo" / "Nothing to redo"; desktops: "Desktop 2", "Desktop 3 · empty", "Already on Desktop 2", "Sent to Desktop 3", "Nothing to send" (no focused window), "No previous desktop"; edge no-op focus_left/right and move "That's the end of the ribbon", focus_up/down "Top of the stack" / "Bottom of the stack" inside a stack of ≥2, "No stack here" for a single window (`show_map` stays true); `move_left`/`move_right` "Moved";
  every width toast says the width it left in whole percent, rounded down, with a no-break space before the % ("Width 66 %"),
  whichever command set it: `cycle_width` / `cycle_width_back` "Width 33 %", `toggle_full` "Full width" / "Back to 33 %" (a dragged width too);
  `toggle_float` "Floating" / "Back in the ribbon"; `stack` "Stacked" (at the first column "No more windows on the left"); `unstack` "Own column"; `cycle_height` "Height 33 %" like the nudges (undo label "height"), or "Stack windows first" on a single window.
- Floating a window re-settles the scroll immediately (the ribbon got shorter), so a later focus from the floating
  window does not scroll a visible anchor.
- Determinism: same event sequence ⇒ same plans. No clocks, no randomness.

### Pinned column
Pinning a column against a display edge is a Plus feature (EDITIONS.md). This edition's core keeps the data model that carries a pin (`Pin`, `map.pin`, `session.pin`, `pinned` on frames and tab bars) so it reads a session a Plus build saved, but no pin ever exists here: a pin command does nothing, and a saved pinned column comes back in the ribbon at its saved slot and width.

## UI (Swift)
- **Menu bar**: a small ribbon glyph with the active desktop number beside it (always). Menu: Pause/Resume (⌃⌥P), Show shortcuts, Settings…, Quit (restores windows).
- **Onboarding** (first launch / no permission): one Liquid Glass window. Headline "Let Ribbon tidy your windows.",
  one button "Allow Accessibility" (opens the System Settings pane), polls `AXIsProcessTrusted` every 0.5s and
  auto-advances to a 4-key cheat sheet → "Done".
- **Ribbon map HUD**: non-activating borderless panel, bottom-center, Liquid Glass capsule.
  Columns drawn as rounded tiles proportional to width, app icon inside, focused tile glows; viewport bracket.
  Appears with spring on `show_map`, lingers 1.2s, fades 250ms. Morphs (glassEffectID) between states.
  Shows `toast` (crossfade) in place of the "You're here" caption when present. Without a toast the caption is prefixed
  "Desktop n · " on desktops other than 1 ("Desktop 3 · empty" when there is nothing to arrange). A calm row of dots sits under the tiles when more than desktop 1
  is in use: dots for 1…max(last desktop with windows, active); accent = here, faint filled = has windows, hollow = empty.
- **Toast pill** (`UI/ToastPill.swift`): toasts show in a glass pill above the strip, as wide as its words and never wider than 620 pt (on a small display, never wider than the usable width less 24 pt each side; the panel is that wide plus 16 pt each side for the glass's shadow). What does not fit gives way in a fixed order: a hint ("⌃⌥Tab to switch") is left out first, then the middle of the headline is shortened ("Tab group: Pages … Keynote"); the full text stays in the accessibility label.
- **Command bar** (`⌃⌥Space`): Dia/Arc-style floating glass panel, center-top. Fuzzy search over windows
  (app + title; windows on other desktops show "Desktop n" as subtitle and picking one switches there) and actions ("Make wider", "Cycle height", "Full width", "Undo", "Pause Ribbon", and "Go to Desktop n" for every other desktop that has windows). ↑↓ Enter, Esc. Jump on Enter.
  Zero-config ranking: picks are remembered (frecency, `count * 0.5^(days/7)`) and boost results below exact-prefix
  matches; the empty list shows windows by focus recency, current window last.
- **Smart widths** (Swift): `width_hint` comes from a built-in bundle-id table (terminals/chat 1/3, browsers/editors/design 2/3);
  when the user resizes a window, that app's width is remembered in UserDefaults and wins next time.
- **Focus ring** (`UI/FocusRing.swift`): a borderless, click-through, non-activating panel (no shadow, `canJoinAllSpaces | fullScreenAuxiliary | transient | ignoresCycle`) ordered directly *below* the focused window with the public `NSWindow.order(.below, relativeTo: CGWindowID)` (verified to work across apps) at that window's `kCGWindowLayer`, so it frames the window and never covers it or anything above. Accent colour (Theme), 4pt, concentric with a 12pt window corner, soft accent glow; Increase Contrast: 5pt, opaque, no glow. Fades in over 0.15 s where it appears and where focus moves to another window (a lone switch fades in from nothing; one within 200 ms of the last, as with a held arrow key, carries on from the opacity the ring has, never below 0.35; Reduce Motion: no dip), glides to a new frame over 0.2s when its own window moves or resizes (instant with Reduce Motion), follows Ribbon's planned frames (also while scrolling) and the live frame during a user drag/resize; floating focused windows get it too. Live frames are the window server's, not AX's. A press on a floating window (its resize zone included) has the ring and the dim follow that window every display frame until the button comes up: macOS reports a dragged or resized window to AX only about ten times a second, so a ring that waited for those reports trailed the window. During a snapshot swipe the swipe overlay draws the ring (the real one waits beneath at the old window): on the focus tile when the swipe starts, travelling with it frame by frame, and at release gliding to the new focus on the tiles' spring while the real ring is placed at the new window at full opacity under the overlay, so the overlay fades onto a ring that is already there. In direct mode it follows its window's last written place every display frame (the full refresh runs at 30 Hz) and fades in again only if it had to hide. Hidden when no managed window is focused, paused, the window is fullscreen/minimised/parked off screen, or another app is frontmost.
- **Three-finger scroll** (`Platform/Trackpad.swift`): exactly three touching fingers whose centroid travels 16 units (pad width = 500) with horizontal dominating arm a scroll (vertical-dominant three-finger swipes are left to macOS). While armed the ribbon follows the fingers like dragged content (fingers right → content right → `scroll_by` with negative `dx`); events are coalesced to ≤60/s and frames are written as x-only position writes, no glide. Lifting a finger sends `scroll_end` with the release velocity (zero if the fingers stopped before lifting); the ribbon then glides on to the rest the core chose, which is a column start (or the end of the ribbon). Gain: one pad width of finger travel = 1.5 screen widths. Without Screen Recording (direct mode) the windows then glide to the settled layout on one spring, as a rigid strip: a window that ends parked keeps sliding off and stops at its parked sliver (it never hangs over the window arriving beside it), one that ends on screen from a parked place waits at its sliver until the strip reaches it; only a window nobody sees leave (off the display) or one parked across a neighbouring display is written at once. The ribbon's tab bars travel with their columns in both modes, from the first movement until the columns have landed: to the tile's x on the overlay, or to the real window's last written x in direct mode, clipped by the display; only the panel's frame changes per display frame (the model and icons are written when what a bar draws changes, icons come from a per-process cache), and they land at the plan's own places.
- **Snapshot overlay** (`Platform/SwipeOverlay.swift`, `Platform/Snapshots.swift`, `Platform/SwipeKit.swift`; needs Screen Recording, independent of the swipe setting): a click-through panel above normal windows and below the Dock, menus and banners slides pictures of the windows (a layer per tile, over a backdrop: the display without the ribbon's windows and without any floating ones; no AX write until release) for swipes and for keyboard moves that only slide windows sideways; without the permission swipes move the real windows (direct mode) and keyboard moves take the AX glide. The first swipe or keyboard glide without the permission offers it once, on a card; Settings says it smooths both.
  - Keyboard moves: the tiles that can be seen while the move runs (on the display before, after or on the way, plus a column) are staged at the old layout, the real windows are written once under them, the tiles spring to the new layout and the layers fade. A run of quick moves adds the few tiles that come into reach to the layers it has: it never stages again and never hides mid-glide. A plan that is no slide (size or row change, window opened or closed, another desktop, drag, Reduce Motion, Dim/Blur/Focus mode) lands a running glide's tiles and fades it while the plan takes the AX path; layers kept for the next move are dropped.
  - Never a gray placeholder in a keyboard glide: every tile seen needs a picture (stale is fine, none is not, a window that changed size since counts as none), otherwise that move takes the AX glide and the missing pictures are captured within 150 ms of a window opening or resizing. Pictures are kept for the whole ribbon, nearest the display first, as many as the ledger holds (14); a tile that crosses the display on a far jump (focus first/last, go to window n) is staged.
  - Fresh pictures: the window that gets the focus and the one that loses it are captured again 120 ms after the move starts, also while the overlay holds the other captures, and swapped in when the glide has landed, right before the fade. The focused window's picture is taken again about every 0.75 s while the user is active, and 0.3 s after an overlay has gone, so a move shows typed text and terminal output as they are.
  - Motion: tiles glide to their final places on a critically damped spring (ω 32). A glide that starts from rest on a keypress starts its clock at the first display frame, never more than one frame before it and not at the key (however late the link wakes, the first frame moves at most a frame's worth, about a tenth of the way at 60 Hz, and the glide shows from that frame); frames are sampled at the time they reach the screen (the display link's target timestamp). A new command mid-glide continues from where the springs are at that moment, with the speed they have. A release keeps the finger speed only for tiles it carries toward their place: a tile never starts away from where the core put it (the layers lead the core by up to 8 px while the fingers move).
  - Landing: once every tile is within 1.5 px and under 60 px/s (and the real windows are written, or 0.3 s have passed) the layers fade out over 0.12 s; the last pixels settle under the fade.
  - Look: every tile has a soft shadow (black, 32 %, 16 pt) on a path rounded like the window, and the focused window's tile is above its neighbours when two pass each other. Windows on the display that no ribbon lays out (floating windows, windows of apps the ribbon leaves alone; normal window level, at least 32 pt showing) are tiles of their own that do not move, over the ribbon when they are in front of every ribbon window in the real stacking order and beneath it otherwise; they are not part of the backdrop. The backdrop is captured again when a window opens, closes, floats or tiles, and on wallpaper or Space changes.
- **Keyboard moves without Screen Recording** (direct mode, `Platform/SwipeWriter.swift`): a move that only slides windows (same size) glides them on one display-paced spring in the ribbon's logical space, all on one clock, and windows that park or appear are held at their sliver. The clock starts at the first display frame at which every app the move writes is ready (its AXEnhancedUserInterface switched off, its earlier writes landed), so an app that answers late does not skip a frame while the others step; an app that has not answered after 80 ms stops holding the others back. A press that retargets glides already in flight (a held key) does not wait: the window it brings in takes the moment of the ones it joins and, if it was parked, starts where the strip has carried it, so it keeps its distance from its neighbour instead of lying over it; a window still sliding off when that press parks it where the last one did slides on with the strip and stops at its sliver. The windows of one app are written one after another, so they land a few ms apart on a slow machine. A plan that resizes a window the user can see (cycle/set width or height, stack, unstack) glides nothing: the resized window and the neighbours that make room for it or fill the room it leaves are written in the same step, an app's windows in an order in which no new frame lies over a window that has not moved yet (two apps' writes are concurrent, so across apps a frame of overlap or gap can remain).
- **Settings**: modifier (⌃⌥ / ⌃⌘ / Hyper), gaps, default width, new-window placement, Focus ring (on), Three-finger scroll (on; hint "If macOS also uses three fingers to switch Spaces, turn that off in System Settings → Trackpad → More Gestures" + "Open Trackpad Settings"; greyed "Not available on this Mac" when MultitouchSupport can't be loaded), a Screen Recording row ("Smooth motion needs Screen Recording", then "Smooth motion is on"; also smooths keyboard moves, shown with or without a trackpad), launch at login (enabled once automatically when onboarding finishes; skipped silently if
  registration fails; the toggle can turn it off).

### Displays (Swift only; the core is unchanged)
- **One ribbon per display**: one `Engine` per display, each with its own 9 desktops and its own `display` event (that display's visible frame, so the menu bar and Dock are respected). Per-display state is keyed by display UUID (`CGDisplayCreateUUIDFromDisplayID`).
- **Routing**: the tracker manages windows on every display. A window belongs to the ribbon of the display holding its centre when Ribbon starts; **new windows open on the display under the mouse** (wherever the app put them, they are moved there), also windows found off every display. A window that comes back (un-minimize, un-hide) returns to its own ribbon. Dragging a window onto another display moves it into that ribbon, placed by where it was dropped.
- **Focused display** = the display of the focused window. ⌃⌥1-9, every command, the HUD, focus ring, toasts, command bar and the menu-bar desktop number follow it.
- **Adjacency** is geometric (OmniWM `macOSAdjacentMonitor`): a display is "right" when its centre is right of yours and the horizontal offset dominates; the nearest wins. A corner-touching staircase therefore reads left/right.
- **Crossing**: at a ribbon's end `focus_left/right` continues to the neighbouring display (landing on its column nearest the entry edge; an empty ribbon shows "<name> · empty"). `move_to_display_left/right` (⌃⌥⇧⌘←/→; no default under the Hyper preset, whose ⌃⌥⌘/⌃⌥⌘⇧ arrows are focus and column moves) and the command bar's "Move window to other display" send the focused window to the neighbour (right of its focused column, width kept, focus follows, toast "Moved to <display>"). "Focus other display" jumps to the other ribbon. Moving between displays is **not** an undo step (undo is per ribbon).
- **Mouse warp** (Settings: "Move the pointer between displays at the edges"; default on only if some neighbouring displays share no edge, i.e. touch at a corner or not at all): pointer within 1pt of an edge with no display beyond it and a neighbour in that direction jumps to the neighbour's facing edge (2pt inside), the other coordinate ratio-mapped and 16pt clear of corners; 50ms cooldown; `CGWarpMouseCursorPosition` plus a synthetic mouseMoved. Listens with an `NSEvent` global monitor for mouse movement (no extra permission).
- **Parking** never lands on another display: the requested side, else the opposite side, else a 1pt corner hang at the home display's bottom-left; least overlap wins.
- **Hot-plug**: on a disconnect the display's windows join the primary's ribbon (appended at the end) and remember their display; when it returns they move back (best effort; desktop assignment is not restored). Arrangement or resolution changes re-lay everything out. With several displays and "Displays have separate Spaces" off, a one-time note explains how to turn it on.

### Launch-time conflict check (`Platform/Conflicts.swift`, `UI/ConflictCard.swift`)
After start (and whenever an app launches, quits or is activated) Ribbon looks for Rectangle, Magnet, Moom, BetterSnapTool, Amethyst, yabai, AeroSpace, OmniWM, ChainYourMac, Loop, Divvy and Spectacle (bundle id; bare daemons like yabai by process name) and for Stage Manager (`com.apple.WindowManager GloballyEnabled`). One glass card at the top right names the first one ("Rectangle is also moving windows") with **Quit Rectangle** (`NSRunningApplication.terminate`) and **Keep both**; Stage Manager offers **Open Settings** / **Keep it on**. Keep both is remembered per app (`dismissedConflicts`). An unanswered card fades after 25s; the menu bar then shows "<App> is also moving windows…" to bring it back. QA: `RIBBON_EXTRA_CONFLICTS="FakeTiler=Fake Tiler"` (process name or bundle id) and `RIBBON_FAKE_STAGE_MANAGER=1`.

### Native tab groups (`Platform/NativeTabs.swift`, `Platform/WindowTracker.swift`)
Windows merged with Window > Merge All Windows, or opened as tabs (Finder, Terminal, TextEdit, Safari ...), stay ONE column. Only the shown tab is in the app's AX window list; the others are live window-server windows with `kCGWindowIsOnscreen` off, so a tab switch, a new tab or a closed tab reads as "one window vanished, another of the same app appeared at the group's frame". The tracker pairs them and reports `replaced(old, new)` (the core's `window_replaced`) instead of `removed` + `added`; hidden tabs are never managed (they are not listed) and only the shown tab is ever written.
- Pairing (`NativeTabs.pairs`, pure): same pid only, one to one. A new window whose frame is within 6 pt (every edge) of the vanished window's frame, or at its corner and within 24 pt of its size (a terminal never lands on the size Ribbon wrote: it snaps to character cells), pairs (closest first); the vanished window's frame is Ribbon's last planned frame for it, or the window server's bounds when it is a hidden tab. Of what is left, an app's single hidden tab and single newcomer pair even at different frames, but only when the newcomer's native tab bar names the hidden tab (a tab is titled like its window, without an "— Edited"-style suffix; an app that titles its tabs otherwise, such as Terminal, gets no such pair). A vanished window still alive off screen (a hidden tab, a window of the Space left, one its app hid) pairs, near or not, only with a newcomer whose tab bar lists 2 or more tabs; a window reported by its destroyed notification was closed and is never a hidden tab. Anything ambiguous pairs nothing: that stays the plain remove + add. A close + open of unrelated windows (other frames, nothing hidden), ⌘H (windows vanish, none appears) and a Spaces switch (windows vanish alive, others appear without a tab bar naming them) never pair. A close and an open at the very same frame cannot be told from a close with its successor and do pair (the new window keeps the column).
- Order of events (`TabPairing`, pure state machine fed by every scan and by destroyed notifications): vanished and appeared in one scan pair at once. A vanished window whose successor is already on screen at its frame (an unmanaged window of the app, per the window server) keeps its place for up to 0.5 s waiting for that window to show up in the AX list, then is removed as usual; any other window that vanishes is removed at once, hidden or not (no delay for ordinary closes, ⌘H, close-to-menu-bar apps, Merge All Windows). A hold that begins looks for its successor itself (rescans at 0.05 / 0.15 / 0.3 / 0.45 s): no notification announces the tab shown in its place. A newcomer is added at once but stays a pairing candidate for 0.5 s: a window that vanishes right after merges into it (core: `window_replaced` with an already-known `new`). The newcomer remembers which managed windows of its app sat at its corner when it appeared (read before its own add re-lays the ribbon); the one of them that vanishes next is the tab it replaces, wherever the ribbon has moved it meanwhile. Destroyed notifications of one app are settled together, so a burst of closes costs one window-server query. ⌘H and app quit drop the holds of that app.
- The controller sends `window_replaced` to the display's ribbon that holds `old`, moves the per-window live state (focus ring, command-bar order, parked floats, remembered original frame for quit-restore) from `old` to `new`, and keeps `home[old]` (the hidden tab returns to the same display). When the new tab's add came first and went to another display (the pointer's), that copy is removed there. The new tab is always written without a glide (its add-time slot is forgotten). If the core left the focus alone (the old tab was not focused) but the new tab has the keyboard, the ribbon follows it like any focus move.
- Known limits: hidden tabs are assumed not to be in the AX window list (seen with TextEdit; an app that lists them would get columns for them); dragging a tab from one group into another is a plain remove + add; if a closed tab's successor is not on screen yet when the destroyed notification arrives, the close is a plain remove + add.

### Float rules
Settings → "Always float these apps" (add from running apps, remove). Stored in `floatApps` (bundle ids); until edited: Calculator, Archive Utility, System Settings. A window of a listed app that Ribbon has never laid out is sent to the core as `window_added` with `floating: true`; one it already laid out (a resume, a move to another display, a Space or full-screen round trip) keeps the state it had. Changing the list (Settings, or the command bar's "Keep <App> out of the ribbon" / "Let <App> join the ribbon") floats or tiles every open and minimized window of that app at once with the core's `set_floating {ids, floating}` (one undo step per display, focus untouched); windows that cannot be resized always float. A window that leaves the ribbon goes where it last floated, else where it was before Ribbon took it in, else to a window-sized rectangle in the middle of the display, never its full-height column. Once floating it has no planned frame, so the drift check, focus ring, dim cutout and drag to reorder leave it alone.

### Settings live
Gap, default width, placement, scroll mode and width steps reach the core as `set_config` (keys merged over the current config, not undoable): the layout stays as it is (stacks, tabs, widths, floats, every desktop) and only what the new values move moves.

### Unresponsive apps
Three AX calls an app cannot complete within 5 s quarantine it: Ribbon stops writing to it and probes with backoff (1, 2, 4… up to 30 s). This is silent. Only an app still hung 10 s later (in practice ~15 s, at a failed probe) is named in a toast, once per hang and at most once an hour per app.

### Session restore (`Core/Session.swift`)
Ribbon snapshots the core (`snapshot` event, no plan log entry) 1.5s after the last change and on quit, only if the layout differs from the last write, to `~/Library/Application Support/Ribbon/session.json` (override: `RIBBON_SESSION_FILE`). Windows are saved as (pid, id, app key = bundle id else app name, title). On launch, when the windows are first discovered, saved windows are matched to live ones: same pid + id + app first, then app key + exact title, then app key in order; then a single `restore_session` rebuilds columns, widths, stacks, desktops, focus and scroll. Unmatched windows are appended normally. Snapshots older than 24h, other versions, or corrupt files are ignored. Not saved while paused.

### Custom shortcuts
Shortcuts sheet: each action's key chip is clickable. Click it and the chip reads "Type shortcut…" (soft accent pulse; static under Reduce Motion), then press the new combo. Esc cancels, Delete/Backspace clears (the action then has no shortcut, shown "Not set"). A combo needs at least one of ⌃ ⌥ ⌘ (F-keys may stand alone). If another Ribbon action uses it the row says "Used by Center — replace?" (Replace unbinds the other action / Cancel); a macOS shortcut (CopySymbolicHotKeys) or a combo another app already holds shows a short warning and nothing is saved. A small reset arrow appears on customised rows and "Reset all" sits at the bottom. While recording, Ribbon's global hotkeys are unregistered, and re-registered on every exit (save, cancel, clear, sheet closed or unfocused).
Storage: `ShortcutStore` keeps overrides in UserDefaults key `shortcutOverrides`, `{actionId: {keyCode, modifiers}}` (physical keycode, Carbon modifier bits; keyCode -1 = cleared). Defaults are never stored: an action without an override uses the modifier preset + layout-aware letter, so changing the preset moves defaults and leaves custom bindings alone. A recorded key is labelled by what the current layout types on it. Desktops 1–9 / ⇧1–9 stay a group (follow the preset); "Back to last desktop" is customisable. The sheet, command-bar hints and menu conflict notice all read the store, so they update live. QA: `echo shortcuts > $RIBBON_CMD_FIFO` opens the sheet.

## Validation
- `cargo test` in core: unit + property tests (random event sequences: invariants — every tiled window
  appears exactly once, frames inside/outside viewport consistent, focus always valid, undo∘cmd = identity; every window is on exactly one desktop,
  windows of inactive desktops are never on screen, focus is on the active desktop or null).
- `ribbon-sim` (core bin): replays JSON event scripts, prints plans → golden files.
- Swift: `swift build`; `RibbonApp --selftest` runs FFI round-trip + HUD render smoke without AX.
- Live: overnight Haiku agent on the Mac mini runs the above and an AX scenario if permission is available.
